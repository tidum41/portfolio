# Design changelog — JOOLA B2B Quick Order

Version history for the wholesale Quick Order / Templates / Catalog design, built as a standalone Tailwind mockup after the Paper canvas workflow ran out of MCP credits mid-build. Kept here so the reasoning behind each round stays attached to the file, not just scattered across chat.

## v1 — Initial 5-screen build

First pass at the full surface: Quick Order (desktop + mobile), Templates, Paddles collection (PLP), and Product Detail (PDP), each extending the real joola.com chrome with wholesale-only additions (tier pricing, MOQ, saved templates). Built directly from a Tailwind/JSX snippet exported from the team's Paper file, continuing the same class conventions.

Known issues at this stage: line-item table used `display:grid` with mismatched column counts (rendered broken — "Product" column wrapped to two lines); generic app-shell styling in places rather than matching the real site.

## v2 — Fixes: real logo, real font, real colors, real radius

- Swapped a placeholder "A JOOLA" text badge for the actual `Joola_Logo_1.avif` at its real live dimensions (200×63, rendered at 100px wide).
- Found and fixed the actual typeface: `FKGroteskNeue` isn't served by the Adobe Typekit link in the theme's `<head>` (that kit only contains `proxima-nova`/`geom-graphic`) — it's self-hosted, and the woff2 files were already sitting in the theme repo. Copied them in and declared real `@font-face` rules.
- Corrected color usage after pulling the real `:root` tokens and DOM usage off joola.com directly: `#485AFF` only appears in one live marketing banner, never as persistent UI — moved the "Authorized Reseller" identity accent to `#2C3EE0` (declared in the token set, unused live) and dropped color from tier-price hints entirely (informational text, not identity).
- Corrected radius from an invented 5–6px to the real `10px` (`--bs-border-radius-input`) on input-style containers, keeping true 5px only where the real PDP buy-box actually uses it (variant pills, swatches).
- Renamed the demo account "Ace Sports Distributors" → "Pickleball Central".
- Reduced uppercase usage to exactly one legitimate case (table column headers); everything else moved to Title Case, matching how the real site treats labels ("Sort By", not "SORT BY").
- Replaced the static "+42 more lines" text with a real expand/collapse control.

## v3 — Layout unification, live interactivity, realistic tiers

- Found and fixed real header/nav markup drift: the `qo-desktop` screen matched the real site's exported JSX (per-nav-item padding); `templates`/`plp`/`pdp` had been hand-rebuilt faster with a different (container-padding) pattern, producing a visibly different header height per screen. Unified all four on the JSX-accurate version.
- Fixed a real bug: every price/SKU number used Tailwind's `font-mono` utility for "alignment," but `--font-mono` was never redefined — prices were silently rendering in system monospace instead of the brand font. Replaced with `tabular-nums` on the same font family.
- Bumped the "Authorized Reseller" status dot from 6px to 8px — present in the DOM the whole time, just too small to register as a deliberate signal.
- Replaced placeholder tier percentages (~14–33% off MSRP, arbitrary MOQs) with numbers grounded in real sporting-goods wholesale convention: keystone-anchored 40–55% off MSRP for paddles/apparel/bags/eyewear, case-pack MOQs (12+) for balls and accessories sold by the box.
- Converted static quantity displays into real `<input>` fields wired to live tier recalculation, with an inline MOQ-violation error state (red border + "Minimum order quantity is X") instead of silent clamping.
- Added expand/collapse line-item previews to Templates cards.
- Removed a fabricated "2 results in 0.4ms" search-latency line and added MOQ to search results.

## v4 — Real layout consistency, table hierarchy, restrained depth

The v3 "layout unification" fixed the header markup but missed the actual visual problem: every screen was wrapped in a centered, drop-shadowed "mockup card" floating on a gray canvas (`flex justify-center py-10 px-6` + `shadow-[0_20px_60px...]` per screen), which made screens impossible to compare side by side — different heights meant different surrounding whitespace, and nothing was pinned to a consistent top edge.

- Removed the canvas wrapper and per-screen shadows entirely. All four desktop screens are now full-bleed white pages starting directly under the sticky dev-switcher bar, top-aligned — tabbing between them now reads as the same website. Mobile keeps a thin border (a device-width indicator) rather than a floating card.
- Found and fixed one real remaining inconsistency: PDP's second bar had a `bg-[#EEEEEE]` tint the other three screens' equivalent bar didn't have.
- Simplified PLP pricing copy: "MOQ 1 · as low as $103.48 at 24+" was one dense line doing two jobs. Split into a plain MOQ fact and a separate two-tone discount hint.
- **Category grouping in the Quick Order table**: reordered the 13 modeled line items into contiguous category clusters (Paddles → Balls → Apparel → Accessories → Bags → Nets & Tables → Eyewear) with small uppercase group-label rows at each boundary. This is the actual answer to "how do we help someone audit a 50-line order" — a flat list gives no way to sanity-check "did I order enough balls"; grouped-by-category is the same pattern NuOrder, Faire, and Amazon Business's own order review use for exactly this reason.
- Two-tone tier hints ("Buy 24+ for **$134.98 ea**" — gray label, bold black price) instead of one flat color, reusing the existing neutral palette rather than adding a new color for hierarchy.
- Restrained, functional depth: a soft upward shadow on the sticky order-summary footer (it's pinned above content — now it looks it), a subtle hover lift on Templates and PLP cards (both are clickable), a faint hover tint on Quick Order rows (so it's clear which row you're about to edit in a long list), and real hover states on black/outline buttons using the site's own documented hover colors (`#282828`) — previously static with zero interactive feedback.

**Flagged but not built this round**: a "+1 case" quantity increment for case-packed goods (balls, apparel, accessories currently require typing exact multiples of 12/24 by hand) — a real efficiency gain, but a bigger interaction change than this pass's scope. Worth a future round.

## v5 — The real header fix, Catalog, Cart/Checkout, Order History, Invoices

v3 and v4 both claimed "layout consistency" and both missed the actual bug. This round started with an exhaustive line-by-line audit instead of another guess, and found it: the announcement bar and header-nav row were already byte-identical across all four desktop screens — never broken. The real inconsistency was the second "wholesale bar" row, where Quick Order/Templates shared one pattern (nav-pill tabs + "Pickleball Central" account switcher) while the paddles listing swapped in a bespoke "Retail shopper / Wholesale" toggle and the PDP swapped in a bespoke breadcrumb, plus a wording mismatch ("Wholesale" vs. "Wholesale pricing active") and PDP quietly collapsing a wrapper div the other three kept. Tabbing between screens, the one thing that's supposed to say "who you are and what account you're ordering under" kept disappearing and reappearing in different shapes — that's what actually read as "the nav isn't consistent."

- **One shared wholesale sub-nav, identical on every screen**: brand dot + label, a tab set, a cart icon, and the account switcher — same markup, same classes, everywhere. The pricing-view toggle moved out of the header and into Catalog's own toolbar, where it actually belongs (it's a demo affordance, not navigation). PDP's breadcrumb moved to its own thin row directly under the shared bar instead of replacing it.
- Dropped the one-off active-tab underline that only ever existed on the paddles listing — it never generalized to PDP and doesn't make sense once "Paddles" is one category among many in a real catalog.
- Fixed a mobile/desktop icon mismatch the audit also caught: the mobile header's bag icon was missing its handle-strap paths, and its search icon was a different SVG construction than the desktop header's. Both now reuse the exact desktop path data, just scaled down.
- **"Paddles — Wholesale" became Catalog**: rounded-pill category chips (13 categories with real counts, matching the reference image's selected/unselected treatment), a "Recommended For You" rail (best-seller / new / reorder-often signals, per the brief — a short curated list, not the whole catalog), and a 12-card grid spanning every category instead of four paddle variants. Extended the v3 keystone-discount/MOQ pricing model to the categories that didn't have one yet (footwear, table tennis rackets/tables/rubbers, court equipment, grips).
- **Cart & Checkout is new**: line items grouped by where they came from ("Added from Quick Order" / "Added from Catalog") so the merge is visible, not just true in theory. Order Summary, an optional PO number (format carries through to Invoices' Order column so the two screens read as the same data), and a Net 30 vs. Credit card payment choice with the account's live credit-line usage shown inline.
- **Order History is new**: reuses the Templates expand/collapse pattern to preview line items without re-deriving a new component. "Placed by" reuses the same Priya M. / Marcus T. names already established as template authors, so the account reads as consistent people rather than new placeholders. Three of the four sample orders share PO numbers with the Invoices screen's sample rows on purpose.
- **Invoices & Terms is new**: credit-line usage card (same $4,200-of-$10,000 numbers as Checkout), and an invoice table with Paid (existing green) and a genuinely new "Due in N days" status, which earns its one new color — pulled from the real site's own declared `--bs-color-warning` (`#FFC107`), verified live rather than guessed, matching the "reuse real tokens" rule from v2.

## v6 — Real nav bug fixed, header identity, header search, cost-clarity sizing

Ported a design pass built in Paper (Quick Order, Catalog, Templates, PDP, Cart & Checkout re-explored there) back into this file — not by copying pixel values wholesale, but by diffing the two and porting only what was a real improvement, since Paper substitutes Helvetica Neue for the real brand font and can't render true two-tone rich text (both harmless Paper-only artifacts, not design decisions).

- **Found and fixed the actual "navigation keeps moving" bug.** It wasn't the header markup (confirmed byte-identical across screens back in v5) — it was the dev-only screen-switcher bar. It used `position: sticky`, and `scrollIntoView({block:'start'})` on screen change interacted with it inconsistently: tall screens (Quick Order, Catalog) could scroll far enough that the sticky bar detached and floated over the content, landing the page content flush at the very top; short screens (Templates, Order History, Invoices) had no room to scroll that far, so the bar stayed in normal flow and pushed their content down by its own height. Every screen switch between a tall and short screen produced a visible ~52px jump. Fixed by making the switcher bar `position: fixed` and giving the screens wrapper a matching `padding-top`, so every screen sits at the exact same offset regardless of its height — confirmed by measuring all 7 desktop screens' top offset before (0 or 52, inconsistently) and after (52, always).
- **Individual identity alongside the org.** The account switcher previously showed only "Pickleball Central" — no sign that a real person is logged in. Added "Priya M." as a small muted line under the company name (org stays primary per your call, person is secondary context) rather than promoting the person over the org or hiding it in the dropdown only.
- **Header global search now shows real results.** The persistent top-nav search was a dead placeholder. It's now click-to-open (same static-example-results convention as Quick Order's own search, per your earlier "keep search static for now" call), and answers "how does wholesale pricing show up here" directly: one line — "Wholesale pricing applied for Pickleball Central" — instead of a badge on every result row, then three results spanning different categories (proving it searches the whole site, not just one section) with wholesale price + MSRP strikethrough, then a link into Catalog for the full list. Deliberately does not duplicate Quick Order's job of searching-to-add a SKU — this is discovery, Quick Order is bulk-add.
- **Cost-clarity sizing pass**, carried over from the Paper exploration: Quick Order's footer total (24px→38px) and per-row line totals (→17px), PDP's unit price (24px→30px), and Catalog card prices (16px→17px) — the numbers that answer "what does this cost" are now unambiguously the loudest thing in their row/section, next to the page's own H1.

## v7 — Scrollbar-shift nav bug, cart badge position, cart spend preview, collapse animation

- **Found the real cause of the top-nav "shift"**: not Templates specifically — any screen short enough to not need a vertical scrollbar (Templates, Order History, Invoices) rendered its centered nav ~5px further right than screens that do scroll (Quick Order, Catalog, PDP, Cart), because the browser's scrollbar eats into the available width only when present. Fixed with a single `html{ overflow-y: scroll }` rule that reserves the gutter permanently, so centering math is identical regardless of content height.
- **Cart badge was floating in dead space.** It was positioned `absolute` relative to the whole nav button, including the button's `py-5` hit-target padding — so the "3" badge sat ~20px above the actual bag icon instead of hugging its corner. Fixed by giving the icon its own tight `relative` wrapper so the badge anchors to the icon, not the padded button.
- **Cart now previews spend at a glance**: the running total ($1,664.60) sits right next to the bag icon in the wholesale bar on every screen, so cost is visible before anyone opens the cart — not just the item count.
- **Order History expand/collapse now has real motion, asymmetric on purpose**: opening stays instant (nothing should make you wait for content you just asked for), closing gets a quick ~180ms exit where each row inside the preview fades and lifts slightly with a 15ms stagger, so the rows read as collapsing away in sequence rather than the whole block just vanishing.

## v8 — Catalog restructure, closing-animation fix, nav-shift root cause

- **Order History's close animation was choppy because only half of it was animated.** The rows faded out smoothly, but the *container* never shrank — it just sat at full height until the JS timeout fired, then the whole block's space vanished in one frame. Fixed by measuring and pinning the block's actual height right before closing, then animating that height to 0 in parallel with the row stagger (both tuned down to ~90–130ms, ease-out) so the rows fading and the space closing now happen together and finish together. Opening is still a plain instant `display` swap — no animation, no delay.
- **Catalog reordered**: category chips now sit directly under the page heading — the primary browse control, first thing you can act on — instead of appearing after a scroll past Recommended For You. The wholesale/retail pricing toggle moved with them, just below.
- **Recommended For You is now visually its own section** (light gray tinted band, top/bottom rule) rather than flowing directly into the chips and grid — it reads as "a curated aside," not as more of the same list.
- **Removed the category eyebrow label from catalog grid cards** — chips already say what category you're looking at; repeating it on all 12 cards was pure redundancy. Recommended For You's cards keep their (differently-colored, blue) category label, since there it's doing real work — explaining why a card from an unexpected category showed up in a personalized rail.

## v9 — Animations removed, Cart layout fixed, stock availability states

- **Removed the Order History expand/collapse animation entirely.** The height-collapse fix still read as choppy in practice, and rather than keep tuning motion that wasn't landing, reverted to a plain instant `display` toggle on both open and close — the same simple, effective interaction Templates' card expand/collapse already used.
- **Fixed Cart & Checkout's "half width" layout.** The line-items column was capped at `max-w-175` (700px) inside a ~1440px container, leaving roughly 340px of dead space to the right of the order-summary sidebar — the actual cause of the page reading as narrow and unbalanced next to every other full-bleed screen. Removed the cap so the column fills the remaining space like Quick Order's table does, and added a matching column header row (Product / Quantity / Line total) so the wider layout reads as a deliberate table, not stretched-out placeholder content.
- **Stock availability states, added to Catalog and Quick Order** — the two "browsing" surfaces, where knowing what's actually available matters before committing to an order size:
  - **In Stock** (the default/common case) shows nothing extra — no badge, no clutter, consistent with this project's running "don't add noise for the expected state" rule.
  - **Low Stock** shows the actual count ("Only 8 left") in the same warning amber already established for Invoices' "Due in N days," rather than a generic "Low Stock" label — a real number is more useful and matches the brief's "trust through transparency" principle.
  - **Out of Stock** (Catalog: Adjustable Court Line Marking Kit; Quick Order: Portable Practice Net) mutes the name/price to gray, replaces the CTA with a disabled "Out of Stock" state, and — on Catalog — swaps the discount hint for a "Notify me when back in stock" link. Quick Order's out-of-stock row additionally drops its `data-tiers`/`data-moq` attributes so the live pricing JS doesn't touch it, and shows a static disabled quantity control and a "—" line total instead of a computed price.

## v10 — Templates isolation bug, Recommended toggle, redundancy pass, real names

- **Found the real cause of "opening one template opens the others."** The JS was already correctly scoped per-card — the actual bug was CSS Grid's default `align-items: stretch`, which makes every card in a grid row match the tallest card's height. Expanding card 1 was stretching cards 2 and 3 to match (207px → 458px, confirmed by measuring), leaving visible blank space in their unopened bodies — reading exactly like "the others opened too." Fixed with `items-start` on the grid so each card only ever takes its own natural height.
- **Catalog: Recommended For You now has a show/hide toggle**, positioned in the section's own header so it stays reachable even when collapsed. Off state removes the rail and the section's bottom padding, so it collapses to just the heading — not a big empty tinted box.
- **Recommended's badges got real, varied justifications** instead of one repeated "#1 Best Seller": "You've Ordered This Most," "Try It Out," "Based On Your History," "Trending With B2B Partners" — matching the three signal types the copy brief actually describes (reorder history, discovery, social proof) instead of leaning on one generic label twice.
- **Low-stock indicator simplified**: dropped the specific count ("Only 8 left" → "Low stock") and merged it into the existing MOQ line instead of giving it its own row — same information, no added card height, and now every catalog card (in-stock, low-stock, and out-of-stock alike) has an identical line count and aligns cleanly in the grid.
- **Removed five purely-repetitive eyebrow labels** ("Quick Order," "Catalog," "Templates," "Cart," "Order History" above their own matching H1s) — the active wholesale-bar tab already says which section you're in; repeating it in text above the heading was pure redundancy. Kept Invoices' eyebrow ("Net 30 credit line · $10,000 limit"), since that one carries real information the H1 doesn't.
- **Cut two more redundant lines**: Catalog's "Pricing reflects your wholesale tier" (already stated one line below by the pricing toggle) and Templates' "Switch accounts above to see a different team's saved orders" (explaining a UI control that explains itself).
- **Order History and Invoices now share the same vertical rhythm** — both screens' table wrapper used a different top padding (`pt-6` vs `pt-8`) for no reason; aligned to `pt-8` on both.
- **Replaced the placeholder names** ("Priya M.", "Marcus T.") with pro pickleball players ("Anna W.", "Riley N.") across the account switcher, Templates, and Order History — same first-name-plus-last-initial format as before, just with names that mean something to the sport.
- **Toggle icon animation retuned**: 150ms linear ease → 120ms with a slight-overshoot back-ease (`cubic-bezier(0.34, 1.56, 0.64, 1)`), on both Order History's and Templates' plus/x icons — faster and reads as a deliberate snap instead of a mechanical rotation.
- **Cart's "half-width" bug** was already fixed last round (line-items column no longer capped short of the container) — verified it's holding.

## v11 — DTC/B2B nav conflict resolved, unified identity pill, no accidental text selection

- **Resolved the DTC/B2B cart conflict.** The main header (shared with the DTC storefront) had a generic bag icon, while the wholesale bar had its own cart control — two icons that could plausibly point to two different carts. Since B2B and DTC share one Shopify storefront and the same top nav, removed the DTC bag icon from the main header entirely for B2B-authenticated views: there is now exactly one cart in this context, and it lives in the wholesale bar where it already has more useful information (a running total) than a bare icon ever could.
- **B2B mode is now indicated in the main JOOLA nav itself**, not just the secondary wholesale bar: a small "Wholesale" tag sits right next to the logo, visible before you even reach the second row.
- **Added "Switch to Retail Store"** in the main header, next to search — the quick way back to the DTC storefront for accounts that also shop retail. (The reverse direction — DTC back to B2B — would live as a "Wholesale Portal" link/account-menu item on the retail side, which isn't part of this file since we don't have a DTC screen built here.)
- **Account identity redesigned as one unified pill** (avatar + org name + person name/role + chevron, all in a single rounded chip) instead of loose floating elements, and **Cart redesigned as its own prominent pill** (black fill, bold "Cart · $amount," red count badge) — both directly inspired by the reference screenshot, adapted to reuse our existing brand-blue avatar treatment and our existing error-red (rather than introducing the reference's un-matched bright accent color).
- **Recommended For You's toggle moved inline with its own heading** (same line, tight coupling — "this switch controls this thing") instead of floating at the far right edge of a wide row disconnected from the description beneath it. The description itself got cut to one punchy line instead of a paragraph, so the section states its own purpose at a glance.
- **Fixed accidental text-highlighting on click-only controls.** Clicking (or slightly dragging while clicking) toggles, chips, and pills was selecting the text inside them like a normal text node. Added `user-select: none` to the Recommended toggle, catalog chips, account/cart pills, the retail/wholesale toggle, payment options, and the Templates/Order History expand icons — the whole class of "click, don't select" controls, not just the one instance reported.
- **Removed Invoices' remaining eyebrow line** ("Net 30 credit line · $10,000 limit"), completing last round's redundancy pass — no screen has an eyebrow above its H1 now. The information didn't disappear: the credit-line-used card's label became "Net 30 credit line used," so the Net 30 fact still shows, just once, in the place it's actually relevant.

## v12 — Real pricing engine everywhere, nav decluttered, Recommended toggle fully mutes its own copy

- **Replaced every hardcoded cart/total number with real, live-computed math.** Quick Order's footer total and line count were already live from v3's tier engine but weren't wired to the header; Cart's subtotal/total and every one of the 7 duplicated header Cart pills were still static strings. All of it now derives from actual quantities × actual prices, recomputed on every change.
- **Found and fixed a real architectural bug in that process**: the first pass at this made Cart's own recompute (`updateCartSummary`) destructively overwrite a separately-accumulated running total that Catalog and Quick Order's "Add to Cart" actions bumped — so using Cart's own qty steppers after adding items from elsewhere silently discarded those additions. The correct fix wasn't reconciling two numbers; it was having only one source of truth. Catalog's "Add To Cart" and Quick Order's "Add All To Cart" now create and insert real `.cart-row` DOM rows into the Cart screen (merging into an existing row by SKU if the item's already there, rather than duplicating), so Cart's from-scratch recompute is always correct because it only ever sums rows that are actually, visibly there. Cart's own `×` remove control is wired for the same reason — it deletes the real row and recomputes, rather than leaving `×` as a decorative glyph.
- **Restored the cart icon** inside the Cart pill (a bag glyph before the "Cart" label) — a prior round's pill redesign had dropped it.
- **Fixed a real nav regression from that same round**: the "Wholesale" tag added next to the JOOLA logo duplicated the identity signal the wholesale bar already gives one row down, and its box collided edge-to-edge with "Switch to Retail Store" next to it. Removed the logo-adjacent tag (identity now stated exactly once, where it has room to mean something) and replaced the bulky "Switch to Retail Store" text link with a compact icon-only control (a two-way arrows glyph, `aria-label`-only for accessibility) sized and spaced to match the existing icon cluster it sits in, rather than as a wide text pill competing with it.
- **Recommended For You's toggle now actually mutes what it's a toggle for.** Its description copy previously stayed visible and unchanged regardless of the toggle's state, which read as broken — turning it "off" didn't visibly do anything to the text explaining the feature. The heading dims and the description hides entirely when off, and the toggle's own label switches between "Showing" and "Hidden" so the control states its own current state.

## v13 — Cart pill simplified, Cart table alignment fixed, retail-switching removed, real athlete names

- **Cart pill is icon-only.** Dropped the "Cart" text label from the pill in every one of its 7 header copies — the bag icon plus the live dollar amount and count badge already say everything the word "Cart" would have added.
- **Fixed a real alignment bug in Cart & Checkout's product column.** The row thumbnail placeholder had two conflicting Tailwind width classes (`w-14` and `size-12`) left over from copying the row pattern — the two rules fought over the element's width and it rendered as a 56×48 rectangle instead of a square, which is what made the whole table read as slightly misaligned even though every text column measured pixel-perfect underneath it. Fixed by collapsing both classes into one (`size-14`, 56×56) on the header's blank spacer, all four static rows, and the JS-generated rows Catalog/Quick Order insert — all four now match exactly.
- **Removed "Switch to Retail Store" from the prototype entirely**, rather than continuing to adjust its icon/position. It was always a decorative link with no real destination behind it, and a static mockup can't demonstrate the actual DTC↔B2B account/session behavior it was standing in for. Documented as a real, unsolved product/engineering challenge in the new `design-considerations.txt` rather than faked further here.
- **Buyer/author names are now real JOOLA-sponsored pickleball athletes' full names** ("Anna Bright," "Lea Jansen") in place of the earlier abbreviated placeholders ("Anna W.," "Riley N.") — confirmed against JOOLA's own published team roster — across the account switcher, Templates, and Order History.
- **Fixed the account switcher's name/role text rendering center-aligned.** The org name and buyer line sit inside a `<button>`, which browsers center-align by default; nothing in the markup had ever overridden it. Added an explicit left alignment so both lines sit flush under the avatar instead of drifting inward whenever one line is shorter than the other.
- **Added `design-considerations.txt`** — a plain-text, topic-organized record of the reasoning behind this build's smaller decisions (navigation/identity, pricing/cost clarity, Catalog, Cart, Templates/Order History, Invoices, color/token discipline), separate from CHANGELOG.md's round-by-round history, plus a "known challenges" section for things deliberately not solved in a static mockup.
- **Added `design-considerations.md`** — a condensed, bullet-point version of the same reasoning, for scanning quickly rather than reading prose.

## v14 — Product Detail retired

- **Retired the Product Detail — Wholesale screen.** This distributor sells at a fixed price, not MOQ-tiered pricing — the entire reason a standalone PDP existed (to show tiered pricing in a focused single-product view) doesn't apply here, so keeping a live PDP tab implied a pricing model this catalog doesn't use. Its dev-switcher tab is now disabled (native `disabled` attribute, dimmed to 30% text opacity, `cursor: not-allowed`, no click), moved to the very end of the switcher, and excluded from the active-tab highlight logic so switching between other screens doesn't reset its dimmed state. The screen's markup stays in the file rather than being deleted, in case fixed-price distributors ever need a product page again — it's just no longer reachable from anywhere in the prototype.
- **Fixed Cart & Checkout's "Quantity" column header.** Every column's text-column x-position was already pixel-perfect (confirmed by measurement), but "QUANTITY" was left-aligned within its column while the quantity stepper it labels is centered inside that same box — so the label sat ~60px to the left of the number it was describing. Centered the header to match the control beneath it; Product (left-aligned content) and Line total (right-aligned content) headers were already correctly matched to their columns.
- **Fixed a real regression from that same alignment pass: the header labels were floating in a tall, mostly-empty bar.** Making the header row's blank corner spacer match the data rows' 56×56 image thumbnail (to fix the "Product" column's x-alignment) accidentally forced the *header* row itself to be 56px tall too, even though that corner is empty in the header — so the header text ended up vertically centered in a much taller box than it needed, floating ~20px away from the divider line meant to anchor it (row height measured 69px before, 30px after). Reverted the header's blank spacer to width-only (`w-14`, no forced height) — it still reserves the same 56px of width for column alignment, but no longer drags the row's height along with it. Text now sits tight against its divider, matching the compact header convention already used on Quick Order, Order History, and Invoices.
- **"Product" header was indented ~72px right of the page's own left margin.** It was positioned to start where the row's *name text* starts (after the thumbnail spacer), rather than where the row itself — and the page's own heading, "Your cart" — actually starts. Removed the header's separate blank spacer cell and let "Product" become the row's first element instead, so its box (and therefore the text) now starts flush at the page's left edge, spanning conceptually over both the thumbnail and name sub-columns — the conventional way a table header handles an icon+text column. Quantity and Line total's positions were unaffected (verified by measurement: their left edges didn't move).

## v15 — One restock, and a way to ask sales

- **Search SKU** sits on the Quick Order toolbar, immediately before Bulk upload. Same 46px height and 6px radius as that control, black fill, 14px bold. The field example is the real Perseus SKU `600558`, not the word "perseus", and the first result uses `products/perseus.jpg`.
- **Recommended chips** are short ("Ordered most", "Try it", "Your history", "New here") and `rounded-[2px]`. The image stays `rounded-[10px]` with the chip inset `top-2 left-2` (8px), so the chip radius is the image radius minus the inset. Reason lines are gone: "Your top reorder this year", "On 4 of your last 5 orders", "New in a category you haven't ordered yet", and "#1 best seller across all B2B partners".
